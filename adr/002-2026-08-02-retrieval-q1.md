# ADR 002 — Retrieval: hybrid search was never justified over lexical

- **Status:** Accepted. Q1/SCALE, Q4, and harvest-as-verdict-source are **closed** — see `FINDINGS.md` §4.
- **Decided:** 2026-08-02 (the reframe that made the question answerable)
- **Recorded:** 2026-08-19, backfilled from `IMPLEMENTATION_PLAN.md`
- **Evidence:** [`PLAN-EXCERPT.md`](proposals/retrieval-q1/PLAN-EXCERPT.md) · [`EVAL.md`](proposals/retrieval-q1/EVAL.md) · [`HANDOFF.md`](proposals/retrieval-q1/HANDOFF.md) · `FINDINGS.md` §2.5 · `eval/results/q1-*-review.md`

## Context

MAST shipped a hybrid retrieval path — FTS5 BM25 fused with vector similarity under RRF —
because that is what retrieval systems do. **Q1 asked whether that default was ever earned.**
It gated M2 (the chunk-store decision, ADR 006) and therefore the whole storage architecture.

The question turned out to be much harder to ask than to answer, and the history of getting it
wrong is the most reusable thing in this ADR:

- **The first three gold sets each encoded their own answer.** In-corpus leakage, then TSDoc
  self-retrieval, then a query-derivation function identical to the index under test. Three
  separate adversarial reviews caught three separate flavours of circularity.
- **An adversarial review (Fable, 2026-08-01) withdrew the verdict outright** and returned Q1
  to `AMBIGUOUS` after it had been called.
- **F16 falsified its own hypothesis twice.** `rrf_k` mis-tuning, then fusion itself. The
  surviving finding is a negative one: **`rrf_k = 60` should not be changed.**
- **The 2026-08-02 reframe was the turning point:** *the metric was the blocker, not the sample
  size.* Rank-position deltas were being read as user-visible wins. They are not — an agent
  reads a window, and a rank change inside that window changes nothing.

That reframe is what made Q1/OUTCOME possible, and Q1/OUTCOME is what closed the question.

## Decision

**Lexical BM25 is the retrieval baseline. Hybrid must beat it at the outcome level to survive,
and it did not.**

The arms, and what each returned:

| arm | verdict |
|---|---|
| Q1/RESERVE | identifier decomposition is **HARMFUL**, not neutral — the stop rule fired |
| Q1/RESERVE-2 | decomposition doesn't survive; the shipped **TRIGRAM** tokenizer does real work |
| Q1/OUTCOME | hybrid vs lexical is **outcome-neutral at k = 12** |
| Q1/ARM-V | V ≈ H everywhere; **F16 stays closed** |
| Q1/SCALE | lexical degrades with scale where hybrid does not — **real, and marginal** |
| Q4 | the win has no nameable class, and the class that matters is **absent** |

Q1/SCALE is the honest complication and is recorded as such: it found a genuine effect. It was
closed as *marginal*, and the one real caveat it left — the identifier stratum at scale — was
discharged by **ranker D** (ADR 004), not by vectors.

### The real-query harvest is an instrument, not a verdict source

`harvest-real-queries.mjs` was built to label queries behaviourally: when an agent's later
`mast_signature`/`mast_exports`/`mast_callers` call in the same session targets something an
earlier `mast_search` returned, the agent has judged that result relevant. That is a relevance
label with provenance predating the experiment — the one thing the synthetic sets could never have.

It returned **n = 0** organic chain-labelled queries, re-checked and still 0 on 2026-08-02,
against a power target of 67. **Harvest-as-verdict-source is closed** (`FINDINGS.md` §4): the
instrument stands, the data does not exist, and Q1 was not permitted to wait on it.

## Consequences

- M2 was unblocked, and resolved as arm D — **ADR 003**.
- The S-ident-at-scale caveat became ranker D's job — **ADR 004**.
- `rrf_k = 60` is frozen. Re-tuning it requires new evidence and an explicit statement of
  what changed.
- The harvest keeps running as the standing real-query instrument (ADR 003, condition 5).

## What this does not claim

Hybrid was not shown to be *worse* than lexical. It was shown to be **outcome-neutral at k = 12
on this corpus and this prompt style**, with the bounded rank advantage it does hold sitting on
a prose stratum that the program's only outcome measurement says never reaches the user. Those
are upper bounds — 22.1% and 39% — **not equivalence claims**. The distinction is what ADR 003's
gap ledger is built on, and collapsing it would misrepresent the whole result.

Q1/OUTCOME's 30 runs were a ~15k-chunk corpus, one prompt style, Bash surface, read-only
investigative tasks. Outcome-at-scale remains **unmeasured**.
